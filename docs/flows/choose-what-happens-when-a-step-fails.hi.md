# तय करें कि स्टेप फ़ेल होने पर क्या हो { #choose-what-happens-when-a-step-fails }

तय करें कि फ़ेल होने वाला स्टेप कितनी बार दोबारा चले, और रन रुके या चलता रहे।

## शुरू करने से पहले { #before-you-start }

- स्टेप एक एक्शन हो, जैसे ऐप का स्टेप या WhatsApp भेजने वाला स्टेप। कंडीशन, पाथ और इंतज़ार वाले स्टेप में ये सेटिंग नहीं होतीं।
- आप ड्राफ़्ट पर हों। पब्लिश किए हुए वर्शन पर ये सेटिंग धुंधली दिखती हैं और बदली नहीं जा सकतीं।

## ये सेटिंग क्या करती हैं { #what-the-settings-do }

**Retry** तय करता है कि स्टेप कुल कितनी बार चलाया जाएगा:

| विकल्प | क्या होता है |
| --- | --- |
| **Default** | Ohanvi तय करता है। ज़्यादातर स्टेप 5 बार तक चलाए जाते हैं। जो स्टेप दोबारा चलाने लायक सुरक्षित नहीं, वे एक ही बार चलते हैं। |
| **Don't retry** | स्टेप एक ही बार चलता है। |
| **3 times** | स्टेप 3 बार तक चलता है। |
| **5 times** | स्टेप 5 बार तक चलता है। |

**Then** तय करता है कि आख़िरी कोशिश भी फ़ेल होने पर क्या हो:

| विकल्प | क्या होता है |
| --- | --- |
| **Stop the flow** | रन **Failed** होकर ख़त्म होता है। आगे के स्टेप नहीं चलते। यही डिफ़ॉल्ट है। |
| **Carry on with the next step** | रन ऐसे आगे बढ़ता है, मानो स्टेप ने कुछ नहीं लौटाया। |

## स्टेप { #steps }

1. फ़्लो को बिल्डर में खोलें और स्टेप चुनें। उसका **Step** पैनल खुलता है।
2. **If this step fails** तक स्क्रॉल करें।
3. **Retry** खोलें और **Default**, **Don't retry**, **3 times** या **5 times** चुनें।

    [SCREENSHOT: If this step fails, जिसमें Retry और Then ड्रॉप-डाउन दिख रहे हों]

4. **Then** खोलें और **Stop the flow** या **Carry on with the next step** चुनें।
5. **Save** पर क्लिक करें, फिर **Publish** पर क्लिक करें।

!!! warning "आगे बढ़ने पर ख़ाली वैल्यू जाती हैं"
    फ़ेल हुए स्टेप के बाद `{{3.value[0].shipment_id}}` जैसी वैल्यू ख़ाली रहती हैं। कोई मैसेज ख़ाली जगह के साथ जा सकता है। **Carry on with the next step** तभी चुनें, जब आगे के स्टेप इस स्टेप के डेटा के बिना भी ठीक चलें।

रन आगे बढ़ जाए, तब भी रन के आउटपुट में फ़ेल हुआ स्टेप **Failed** ही दिखता है। देखें [किसी रन का आउटपुट विस्तार से पढ़ें](read-a-runs-output.md)।

### Retry की सेटिंग चुनें { #pick-a-retry-setting }

- मैसेज भेजने वाले स्टेप के लिए **Don't retry** चुनें। टाइमआउट के बाद दोबारा कोशिश होने पर मैसेज दो बार जा सकता है।
- सर्च और पढ़ने वाले स्टेप के लिए **Default** रहने दें। इन्हें दोबारा चलाना सुरक्षित है।
- पहले से सेव की गई कोई वैल्यू, जैसे **2 times**, वैसी ही दिखती है। पैनल खोलने से वह नहीं बदलती।

कुछ एक्शन कभी दोबारा नहीं चलाए जाते, क्योंकि दोबारा चलाने से काम दोहरा हो जाएगा। Shiprocket का **Create an order** ऐसा ही एक्शन है। इनके लिए **Retry** धुंधला दिखता है और साथ में **Retries are off for this operation.** लिखा होता है।

## समस्या का समाधान { #troubleshooting }

| समस्या | कारण | समाधान |
| --- | --- | --- |
| **Retry** धुंधला है और **Retries are off for this operation.** लिखा है | इस एक्शन को दोबारा चलाने से काम दोहरा हो जाएगा। | कुछ ठीक करने की ज़रूरत नहीं। स्टेप एक बार चलता है। |
| दोनों ड्रॉप-डाउन धुंधले हैं | आप पब्लिश किया हुआ वर्शन देख रहे हैं। | ड्राफ़्ट खोलें, फिर सेटिंग बदलें। |
| ग्राहक को एक ही मैसेज दो बार मिला | टाइमआउट के बाद भेजने वाला स्टेप दोबारा चला। | उस स्टेप में **Retry** को **Don't retry** पर करें। |
| कोई मैसेज ख़ाली जगह के साथ गया | पिछला कोई स्टेप फ़ेल हुआ, और उसका **Then** **Carry on with the next step** पर है। | उसे **Stop the flow** पर करें, या वह फ़ील्ड हटाएँ जिसे उस स्टेप का डेटा चाहिए। |
| रन **Succeeded** दिखाता है, पर एक स्टेप **Failed** है | वह स्टेप **Carry on with the next step** पर सेट है। | **Latest output** में स्टेप की गड़बड़ी पढ़ें, फिर स्टेप ठीक करें। |
